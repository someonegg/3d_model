# 开发指南

项目安装与模型目录见 [项目首页](../README.md)。本页面向模型开发者，说明源码接入、构建、发布和本地验证；打印使用说明保存在各模型 README 中。

## 目录与常用命令

`models/<ID>/` 保存模型源码：清单、用户说明、参数、`src/` 脚本、`references/` 素材和导入模型的 `source/`。ID 必须与目录名一致；每个非隐藏的直接子目录都必须有 `model.json`。

生成模型及内部报告位于 `build/models/<ID>/`，临时构建、测试和切片文件位于 `tmp/`，最终站点位于 `dist/`。这些目录不提交 Git。

开发服务支持透传 Vite 参数。修改模型后手动运行 `npm run build`；服务监听资源变化，但不会自动构建模型。测试或独立模型库可用 `--library-root <根目录>` 指定包含 `models/` 的目录。

## 接入模型

复制 [清单模板](../tools/model.template.json) 到 `models/<ID>/model.json`，添加说明和脚本。没有专项验收时，删除模板中的 `verify` 及对应输入。

| 字段 | 约定 |
| --- | --- |
| `build` | 必填 Python 构建脚本，路径相对模型目录，必须列入 `inputs` |
| `verify` | 可选专项验收脚本，同样列入 `inputs`；可生成报告，不得修改已校验几何或 glTF 依赖 |
| `inputs` | 构建依赖文件，相对模型目录；共享工具和上游产物可使用 `../../tools/...`、`../../build/models/<ID>/...`，不得越出模型库根目录 |
| `depends_on` | 上游模型 ID；对应产物仍须列入 `inputs`，未知依赖及循环会报错 |
| `variants` | 模型变体列表，第一项为默认视图；每项可覆盖 `purpose`、`units`、`up` |
| `preview` / `readme` | 构建目录中的主预览图 / 自动从源码复制到构建目录的用户说明 |
| `artifacts` | 参与完整性校验的附加几何构建产物，包括内部验收报告 |
| `publish` | 额外发布资源白名单，如预览、模型、说明和 ZIP；不包含源码、参数、参考素材或内部报告 |
| `assembly` | 可选交互装配 GLB，须同时列入 `artifacts`、`publish`；数据协议和生成方法见 [装配动画参考](assembly.md) |
| `bundle` | 可选下载包配置路径，相对模型目录，见下文 |

打印变体只支持 STL，使用声明的实际单位和向上轴。GLB/glTF 必须为展示用途、米单位、Y 向上。

构建与验收脚本从 `MODEL_OUTPUT_DIR` 读取输出目录，不得回退写入源码；通过 `__file__` 定位参数和素材。使用 `main()` 入口，导入模块时不生成文件。公共运行器提供脚本目录、仓库和共享工具的导入路径。

### 用户说明

每个模型 README 按“简介与尺寸 → 下载 → 打印 → 装配与使用 → 核心参数 → 验证状态”组织；无装配步骤的模型省略该节。保留离线打印和装配所需信息，参数注明来源，区分装配尺寸与打印排版尺寸。按模型需要补充换色、五金清单或配合试打步骤。说明描述当前模型；改版经过、旧参数比较及试验演进保留在 Git 历史中。

模型说明会复制到构建目录、站点及已配置的下载包。下载和图片链接使用相对生成目录的路径，且只能指向已发布资源；不要链接源码、参数或内部报告。文件存在于 `artifacts` 并不意味着已发布。项目首页的模型索引使用源码 README 链接。

验证状态分别说明几何验收、切片检查和实物验证。只有对应版本报告与最终文件一致时才标注通过；打印时间与耗材估算注明条件。历史版本检查不能作为当前版本的验收依据。切片入口和报告复核方法在本指南维护；模型说明只保留检查结论、打印风险与实物验证状态，不罗列检查计数、哈希或 CLI 日志。

### 导入已有模型

导入已有模型时，使用 [导入清单模板](../tools/import-model.template.json) 和 [复制脚本模板](../tools/import-build.template.py)，将源模型、纹理、缓冲区及预览放入 `source/` 并列入 `inputs`。公共流程将 GLB/glTF 转为自包含 GLB，校验后用于网页预览和下载；清单中的 `.gltf` 变体会发布为同名 `.glb`，需避免路径冲突。导入源文件提交 Git，外部依赖不随变体单独发布。

## 增量构建与下载包

构建按模型依赖顺序执行：几何生成与格式转换 → 几何校验与专项验收 → 公共资源复制及可选 ZIP → 整体替换模型输出 → 发布站点。构建应单进程串行执行。

模型输出和站点均先暂存；构建或校验失败时保留原有产物。目录替换先将目标移到备份，再将暂存目录移到目标，失败时尝试回滚；两步之间目标路径短暂不存在，不保证原子切换。

`validation.json` 记录几何配置、构建输入、公共运行与验收代码、Python 依赖环境及几何产物指纹。缓存有效时跳过几何生成与验收；输入变化、产物缺失或损坏时重建。共享算法需由使用它的模型显式列入 `inputs`。前端和开发服务代码不参与几何缓存。

需要下载包时，在清单中设置 `"bundle": "bundle.json"`，将 ZIP 文件名加入 `publish`，按 [打包模板](../tools/bundle.template.json) 配置：

- `file`：ZIP 相对路径。
- `files`：文件列表；每项的 `from` 为 `source`（模型源码目录）或 `output`（模型构建目录），`path` 同时为输入路径和包内路径。

模型 `publish` 使用字符串声明已有构建产物，或用 `{"from": "source", "path": "references.md"}` 声明源码目录中的说明、图片或 PDF，按原相对路径复制。README 自动复制，不应重复声明；模板中不需要的发布项应删除。复制禁止越界、重复目标、内部资源及覆盖几何产物。

打包拒绝越界、重复归档路径、缺失文件、压缩包自身及覆盖几何产物。固定排序、时间戳、权限和压缩参数保证相同输入生成相同 ZIP。包中只放用户模型、预览和说明。

每个模型都生成 `packaging-validation.json`，记录公共复制、可选 ZIP 的配置、代码及输入和产物指纹。README、源码发布项和 ZIP 变化或损坏仅更新公共阶段；几何变化和 `--force` 更新两个阶段。仅清理打包报告记录且不再被几何或发布引用的产物。

生成脚本使用的源文件须列入几何 `inputs`；仅供公共复制或打包使用的配置、说明和 ZIP 不应列入几何 `inputs`、`artifacts`。

## 发布与开发服务

`npm run build` 重新组装 `tmp/site/`，检查 TypeScript 并构建前端，通过后发布到 `dist/`。发布严格检查几何及打包报告，只包含前端、变体模型、预览、用户说明和 `publish` 白名单资源。`catalog.json` 提供展示字段、资源地址、修订标识和几何校验摘要，不公开完整报告或输入指纹。

开发服务使用相同白名单，监听模型清单、声明输入、用户说明、打包配置及其源码输入和构建产物，变更后刷新页面；README 从构建目录读取。独立手工脚本不触发模型库刷新。

将 `dist/` 上传到 HTTP 静态服务，可部署在根路径或子目录，不支持 `file://`。站点发布拒绝空模型库，也不能覆盖源码、模型产物或其它非空目录。

## 手工切片

切片独立于构建，读取 `build/models/<ID>/`，不需要模型清单或几何验收报告。应先运行构建，确保输入是当前版本；查看模型脚本入口及参数：

```sh
.venv/bin/python tools/run_model.py models/<ID>/src/slice.py --help
```

`--studio`、`--profiles` 指定 Bambu Studio 与配置，默认路径对应 macOS 的 `/Applications/BambuStudio.app/`；其它安装位置或系统需显式指定。`--output-dir` 指定独立工作区，不得覆盖源码、模型产物或站点。工作区保存 3MF、G-code、预览、日志和 `slicing-validation.json`。

| 模型 ID | 默认工作区 | 模型专用选项与检查 |
| --- | --- | --- |
| `keyboard-fidget-fdm` | `tmp/keyboard-fidget-slicing/` | `--collect-only` 复核已有 3MF 配置、归档几何、弹臂与底盖斜坡路径 |
| `retractable-shuriken-fdm` | `tmp/retractable-shuriken-slicing/` | `--prepare-only` 生成配置并输出 Studio 命令数组；`--collect-only` 核对归档几何及弹舌、钩柱、钩头和销柱路径；两选项互斥 |
| `star-chain-fdm` | `tmp/star-chain-slicing/` | `--collect-only` 核对已有切片的归档几何及卡位、固定端防脱、粗榫支承和锁销孔路径 |
| `volvo-xc60-2022` | `tmp/xc60-slicing/` | `--only` 选择切片文件；`--model-dir` 必须指向当前模型构建目录 |

直接切片时保存 `studio.log`。收集已有切片时，软件版本使用原日志；手里剑也读取并核对 G-code 头部，不以当前安装版本代替原生产版本。

切片共用 `tools/slicing.py`，模型脚本提供排版、配置和专项检查。成功后原子更新报告，失败或输入变化时保留上次报告。模型变化后需手工重新切片；切片代码与结果不参与构建缓存或站点发布。

### 报告复核

- 几何报告 `build/models/<ID>/validation.json` 的 `files` 记录最终文件尺寸、单位、用途及 SHA-256；专项结论在模型生成的附加报告中。构建流程同时校验源码与产物指纹。
- 切片报告的 `source_sha256` 及各盘 `sha256` 应与当前构建文件一致；核对配置、盘警告、关键路径和 `physical_print_test`。报告存在或切片返回成功，不代表没有警告或已经实物验证。
- 支持 `--collect-only` 的模型可复核已有切片与当前 STL；其它模型在输入变化后应重新切片。
- 日志提示保留在本地报告中；影响打印成形的风险同时写入模型说明。

## 测试与验收

| 命令 | 验证范围 |
| --- | --- |
| `npm test` | 构建流程与独立算法 |
| `npm run check` | 前端及浏览器测试类型 |
| `npm run test:e2e` | 生成夹具、构建正式模型和站点、执行浏览器检查；首次需运行 `npx playwright install chromium` |
| `npm run format:check` | 格式 |

模型改动应校验最终导出文件的实际尺寸、细节和工艺要求；FDM 浅浮雕遵循 [fdm-relief](../.agents/skills/fdm-relief/SKILL.md)。涉及网页展示、资源或下载时执行浏览器检查，按实际完成的验证报告结果。
