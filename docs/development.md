# 开发指南

项目安装与模型目录见 [项目说明](../AGENTS.md)。本页面向模型开发者，说明源码接入、构建、发布和本地验证；打印使用说明保存在各模型 README 中。

## 目录与构建

`models/<ID>/` 保存模型源码：清单、用户说明、参数、`src/` 脚本、`references/` 素材和导入模型的 `source/`。ID 必须与目录名一致；每个非隐藏的直接子目录都必须有 `model.json`。

生成模型及内部报告位于 `build/models/<ID>/`，临时构建、测试和切片文件位于 `tmp/`，最终站点位于 `dist/`。这些目录不提交 Git。

在仓库根目录执行：

```sh
npm run build                  # 增量构建全部模型及站点
npm run build -- --force        # 强制重建全部模型及站点
npm run dev                    # 增量构建模型后启动开发服务
```

仅构建一个模型及其上游依赖，可使用公共运行器；此命令不更新站点：

```sh
node tools/python.mjs build keyboard-fidget-fdm
```

开发服务启动后，修改模型或 README 仍须手动构建；文件监听只刷新页面，不执行构建。Vite 参数可通过 `npm run dev -- --port 5174` 透传。独立模型库使用 `npm run build -- --library-root <根目录>`，该根目录须包含 `models/`。

## 接入模型

复制 [清单模板](../tools/model.template.json) 到 `models/<ID>/model.json`，添加说明和脚本。没有专项验收时，删除模板中的 `verify` 及对应输入。

| 字段 | 约定 |
| --- | --- |
| `id` / `name` / `description` | 目录 ID、展示名称及简介 |
| `purpose` / `units` / `up` | 默认用途、单位和向上轴，变体可覆盖 |
| `build` | 必填 Python 构建脚本，路径相对模型目录，必须列入 `inputs` |
| `verify` | 可选专项验收脚本，同样列入 `inputs`；可生成报告，不得修改已校验几何或 glTF 依赖 |
| `inputs` | 构建依赖文件，相对模型目录；共享工具和上游产物可使用 `../../tools/...`、`../../build/models/<ID>/...`，不得越出模型库根目录 |
| `depends_on` | 上游模型 ID；对应产物仍须列入 `inputs`，未知依赖及循环会报错 |
| `variants` | 模型变体列表，第一项为默认视图；每项可覆盖 `purpose`、`units`、`up` |
| `preview` / `readme` | 构建目录中的主预览图 / 自动从源码复制到构建目录的用户说明 |
| `artifacts` | 参与完整性校验的附加构建产物，包括内部验收报告 |
| `publish` | 额外发布资源白名单，如预览、模型、说明和 ZIP；不包含源码、参数、参考素材或内部报告 |
| `assembly` | 可选交互装配 GLB，须同时列入 `artifacts`、`publish`；数据协议和生成方法见 [装配动画参考](assembly.md) |
| `bundle` | 可选下载包配置路径，相对模型目录，见下文 |

打印变体只支持 STL，使用声明的实际单位和向上轴。GLB/glTF 必须为展示用途、米单位、Y 向上。

构建与验收脚本从 `MODEL_OUTPUT_DIR` 读取输出目录，不得回退写入源码；通过 `__file__` 定位参数和素材。使用 `main()` 入口，导入模块时不生成文件。公共运行器提供脚本目录、仓库和共享工具的导入路径。

### 用户说明

每个模型 README 按“简介与尺寸 → 下载 → 打印 → 装配与使用 → 检查结果”组织；无装配步骤的模型省略该节。保留离线打印和装配所需信息，区分装配尺寸与打印排版尺寸。按模型需要补充换色、五金清单或配合试打步骤。说明描述当前模型；改版经过、旧参数比较及试验演进保留在 Git 历史中。

模型说明自动复制到构建目录与站点；需要离线说明时，在下载包配置中加入 README。下载和图片链接使用相对生成目录的路径，且只能指向已发布资源；不要链接源码、参数或内部报告。文件存在于 `artifacts` 并不意味着已发布。项目说明的模型索引使用源码 README 链接。

几何与切片检查只记录与最终文件一致的已有结果；打印时间与耗材估算注明条件。实际打印效果仅在有用户反馈时记录，没有反馈就省略，不添加空白状态、免责段落或未执行的实物验收清单。模型说明保留检查结论、验证边界与具体成形问题，切片操作和报告细节见 [切片与验证](slicing.md)。

内部参数、尺寸关系、设计考量及详细验证方法和数值保存在模型源码目录的 `design.md`。该文件不加入发布白名单或下载包，公开 README 不链接它。

### 材料选择

普通外壳、底座、键帽及装饰件可用普通 PLA；弹性件按各模型说明选择 PLA Tough+，使用对应材料预设。弹性件保留粗壮连接、根部圆角与刚性过行程止挡。模型线性筛查采用的模量来源见 [PLA Tough+ 数据表](https://store.bblcdn.com/s1/default/7130c176eac54e928d650e48d8b12d72/new_Bambu_PLA_Tough_Technical_Data_Sheet.pdf)；表中试样经过退火与干燥处理，不能直接视为打印件实测性能。

### 导入已有模型

导入已有模型时，使用 [导入清单模板](../tools/import-model.template.json) 和 [复制脚本模板](../tools/import-build.template.py)，将源模型、纹理、缓冲区及预览放入 `source/` 并列入 `inputs`。公共流程将 GLB/glTF 转为自包含 GLB，校验后用于网页预览和下载；清单中的 `.gltf` 变体会发布为同名 `.glb`，需避免路径冲突。导入源文件提交 Git，外部依赖不随变体单独发布。

## 增量构建与下载包

模型按依赖顺序构建：几何生成与格式转换 → 通用几何校验与专项验收 → 公共资源复制及可选 ZIP → 替换模型输出。全部完成后再构建并发布站点；构建应单进程串行执行。

模型输出和站点先暂存，校验成功后替换目标目录；失败时保留原有产物。目录替换不保证原子切换。

`validation.json` 记录几何配置、构建输入、公共运行与验收代码、Python 依赖环境及几何产物指纹。缓存有效时跳过几何生成与验收；输入变化、产物缺失或损坏时重建。共享算法需由使用它的模型显式列入 `inputs`。前端和开发服务代码不参与几何缓存。

需要下载包时，在清单中设置 `"bundle": "bundle.json"`，将 ZIP 文件名加入 `publish`，按 [打包模板](../tools/bundle.template.json) 配置：

- `file`：ZIP 相对路径。
- `files`：文件列表；每项的 `from` 为 `source`（模型源码目录）或 `output`（模型构建目录），`path` 同时为输入路径和包内路径。

`publish` 使用字符串声明构建产物，或用 `{"from": "source", "path": "references.md"}` 声明源码目录中的说明、图片或 PDF，按原相对路径复制。README 自动复制，不应重复声明；模板中不需要的发布项应删除。

ZIP 按 `files` 显式收录，不会自动包含 `publish` 中的资源。包内相对链接所需的文件也须加入清单。发布与打包共用公共资源校验，禁止内部报告及装配／几何元数据，拒绝越界、重复目标、缺失文件及覆盖几何产物；ZIP 还禁止收录自身。相同输入生成相同 ZIP。包中保留离线打印所需模型、预览和说明。

`packaging-validation.json` 校验公共复制与 ZIP。说明、源码发布项或打包配置变化，以及公共产物损坏，仅更新公共阶段；几何变化和 `--force` 更新两个阶段。

构建入口负责导出编排，几何、预览与装配动画按职责保存在模型的 `src/`；简单入口无需空模块。主要尺寸、间隙和离散精度使用 `parameters.json`，派生尺寸与局部造型公式留在代码。书签共用 `tools/bookmark_relief.py`，模型参数保留各自的裁剪与滤波设置，公开预览在构建阶段生成，专项验收独立读取最终 STL。

生成脚本使用的源文件、参数和共享构建代码须列入几何 `inputs`；仅供公共复制或打包使用的配置、说明和 ZIP 不应列入几何 `inputs`、`artifacts`。

## 发布与开发服务

`npm run build` 重新组装 `tmp/site/`，检查 TypeScript 并构建前端，通过后发布到 `dist/`。发布严格检查几何及打包报告，只包含前端、变体模型、预览、用户说明和 `publish` 白名单资源。`catalog.json` 提供展示字段、资源地址、修订标识和几何校验摘要，不公开完整报告或输入指纹。

开发服务使用相同资源白名单，监听模型清单、声明输入、用户说明、打包配置及其源码输入和构建产物；README 从构建目录读取。未声明的独立脚本不触发模型库刷新。

将 `dist/` 上传到 HTTP 静态服务，可部署在根路径或子目录，不支持 `file://`。站点发布拒绝空模型库，也不能覆盖源码、模型产物或其它非空目录。

## 切片与报告

切片独立于模型构建，`src/slice.py`、`slicing.json` 与共享切片代码不参与几何缓存。执行入口、各模型选项及报告复核见 [切片与验证](slicing.md)。

## 测试与验收

| 命令 | 验证范围 |
| --- | --- |
| `npm test` | 构建流程与独立算法 |
| `npm run check` | 前端及浏览器测试类型 |
| `npm run test:e2e` | 生成夹具、构建正式模型和站点、执行浏览器检查；首次需运行 `npx playwright install chromium` |
| `npm run format:check` | 前端、工具及配置格式；不检查 Markdown 或 Python |

通用几何校验检查打印变体的封闭性、绕序、退化面和各连通实体的正体积；展示变体不要求封闭。专项验收通过脚本退出码判断，公共流程不解释报告中的 `passed` 等业务字段，因此须另行阅读专项报告的结论与未解决项。

模型改动应校验最终导出文件的实际尺寸、细节和工艺要求；FDM 浅浮雕遵循 [fdm-relief](../.agents/skills/fdm-relief/SKILL.md)。涉及网页展示、资源或下载时执行浏览器检查，按实际完成的验证报告结果。
